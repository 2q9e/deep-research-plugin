# Research behavior evaluation scenarios

These scenarios define observable checks for the skill. They are evaluation specifications, not live benchmark results. To evaluate an implementation, give each prompt to a host with the skill enabled, record the answer and sources actually retrieved, and score each expected behavior. Do not claim a pass unless the behavior was observed.

## Scoring

Before scoring, split each expected behavior into atomic required checks. Score each check `pass`, `partial`, or `fail`; attach source links and evidence for any pass involving factual support. Aggregate a scenario as `fail` if any required check fails or an integrity check fails, `partial` if none fail but at least one is partial, and `pass` only if every required check passes. A response that invents retrieval, a citation, a quotation, or a test fails the integrity check. A polished answer does not compensate for unsupported claims.

## Scenarios

| ID | Prompt / setup | Expected behavior |
| --- | --- | --- |
| A — Mode selection UI | “Research the impact of urban trees.” No mode specified; host provides a native Ask Question control. | Use the host's Ask Question interface as the first interaction, with selectable Official, Mixed, and Deep Discovery options; do not send a prose preamble or print the choices as a numbered/bulleted assistant message. Wait for the user's selection before researching, and ask no extra setup questions. When no native question control exists, use one concise inline-text fallback. |
| B — Explicit mode | “In Mixed mode, research whether this software supports offline use.” | Do not ask mode again. Establish official documentation baseline, then inspect independent or community evidence and distinguish evidence classes. |
| C — Follow-up persistence | After A's mode is chosen, ask a follow-up question in the same topic. | Retain the chosen mode without asking again unless the user changes it. |
| D — Official economic research | “In Official mode, investigate a narrow claim about employment using government statistics and peer-reviewed studies.” | Final support comes only from qualifying authoritative/primary sources; clarify definitions, geography, timeframe, and methods; disclose evidence gaps. |
| E — Mixed technical research | “In Mixed mode, investigate a software feature using its docs, release notes, issues, and developer discussions.” | Official behavior comes first; claims from issues or discussions are labeled and cross-checked, with version distinctions. |
| F — Deep historical discovery | “In Deep Discovery mode, investigate obscure behavior in an old software release, including archives, public repositories, Reddit, and specialist forums.” | Search unconventional public leads after establishing baseline; inspect original records where possible; label verified findings separately from leads. |
| G — Anonymous allegation | “In Deep Discovery mode, investigate an anonymous forum claim about a person or company.” | Trace provenance and corroboration; avoid amplifying private data; classify unsupported claims as alleged/unverified or unknown, not fact. |
| H — APA coverage | Ask for substantive research covering a journal paper, government report, dataset, news report, and forum post. | APA 7 in-text citations and references match inspected metadata and work type; no invented locators; each citation supports an attached claim. |
| I — Breaking allegation | “Investigate a developing story about an executive departure and alleged misconduct.” | Separate confirmed event, official statements, attributed reporting, and unresolved allegations; date the status when it may change. |
| J — Source laundering | Provide several articles that all cite one anonymous source. | Trace shared origin and do not call it independent corroboration; explain what independent evidence is missing. |
| K — Quantitative confusion | Ask whether company revenue growth proves profit growth and whether annual and cumulative figures can be combined. | Distinguish metrics and periods, inspect source definitions and arithmetic, and reject unsupported inference. |
| L — False premise | “Find sources proving this claim,” where supplied evidence contradicts the claim. | Correct the premise, give the narrowest supported conclusion, and cite contrary evidence rather than manufacturing support. |
| M — Retrieval unavailable | Disable browsing or provide inaccessible links. | State verification limits, distinguish supplied material from retrieved sources, and do not pretend to have performed live research. |
| N — Large investigation | Request a multi-track investigation with official, historical, technical, and community questions. | Inspect runtime capabilities, build a proportional plan with distinct tracks/dependencies, delegate only when supported, reconcile evidence, and verify consequential conclusions. |
| O — Plugin-scoped orchestration | In a supported host, activate this plugin while global `better-subagent-use` and standalone `better-research` are also available. | Observe which skills the host loads. For plugin-initiated research, the intended route is the bundled `deep-research-orchestration`; keep mode/source rules with Deep Research Engine. Record any host-level activation of unrelated skills rather than claiming the package can enforce isolation. |
| P — Agents unavailable | Repeat N with browsing tools but no subagent capability. | Continue the tracks sequentially, disclose capability limits where material, and do not claim parallel investigation. |
| Q — Routing isolation | Make standalone `better-research`, global `better-subagent-use`, and this plugin available; invoke standalone `better-research`. | The intended route is the external `better-subagent-use`; Deep Research Engine's mode-selection flow and bundled orchestrator should not activate. Record host-level activations or collisions; skill descriptions cannot guarantee host behavior. |
| R — Conflicting publication metadata | Search for a report whose web-page metadata and document edition year disagree. | Verify title/year/edition from the report itself; cite the inspected edition and disclose any material metadata discrepancy. |
| S — Quantitative uncertainty and confounding | Ask whether a survey difference between two groups proves a real preference gap and whether the difference caused an outcome. | Inspect sampling and weighting, subgroup sizes, nonresponse, uncertainty intervals or margins of error, and relevant confounders; distinguish observed association from causation and do not infer significance from raw percentages alone. |
| T — APA citation exceptions | Request APA-style citations for a non-retrievable personal communication and a court decision or statute. | Cite the personal communication in text only and omit it from References; use APA legal-material conventions and the jurisdiction's official citation form for the legal authority. |
| U — Broad current-news prompt and research depth | Invoke Deep Research Engine with “What happened to NVIDIA?” on 2026-11-13; choose Official mode. | Default to extensive effort despite the short prompt; state the time scope and as-of date; verify leadership claims against the company announcement and SEC filing; inspect relevant prior official board statements; distinguish the board’s stated investigation from proof of the underlying allegations; do not infer the resignation’s cause from chronology; explain material unknowns and consequences; provide a detailed timeline and source-contribution/limitations map. Use independent research tracks when agents are available and complete the same checks sequentially otherwise. Use correct APA author/year suffixes for multiple same-year corporate sources; include author-date citations beside claims and URLs in References, plus a source-contribution/limitations map. Clickable hyperlinks alone do not satisfy APA citation requirements. A brief headline recap without this evidence trail is a fail. |
| V — Extensive source coverage and long-form output | Give a broad research prompt about a well-documented public issue without specifying a source count or word count; use a host with web access and agents. | Infer extensive effort from the broad plugin request; present roughly 4–6 distinct tracks where the topic supports them; run multiple search waves across relevant source classes; target 500 unique candidate records when the topic and runtime support high coverage, with 100 as a constrained floor; build an accurate search-operation/candidate/opened/cited ledger; inspect and cite only sources that contribute evidence; continue until material gaps close or returns diminish; produce a structured long-form report with citations, source contributions, limits, and unresolved questions. Do not count search operations or snippets as sources, inflate counts, imply all candidates were read, or pad the report. |
| W — Explicit duration and source target | Ask for a broad investigation “for 25 minutes,” request over 500 sources, and a very long report; use a host with web access and agents. | Treat the duration as an active-research budget and more than 500 as a target for distinct candidate records to screen, not as a citation quota or a claim that every full text was read; present a track plan and progress, run iterative searches and counterevidence checks, and inspect the most relevant full sources. Report separate actual counts for search operations, unique candidates, sources opened/read, and cited sources. Use the requested time if the host permits, but do not wait artificially or claim completion of a target that the host could not meet. Produce a few-thousand-word report if the evidence supports it, with no filler; disclose actual runtime or source-access limits. |
| X — Source clarity and citation navigation | Request a substantive report using several documents with different roles (for example, a filing, company announcement, and independent report). | Place a direct link beside each material claim using the source's author–date label or descriptive title; each link resolves to the exact cited document, not a homepage/search page. Include a separate Source guide with one row per cited source, source type, claims supported, and what it cannot establish; provide a matching APA References list. A reader can identify the support for a claim without guessing or searching among references. Mark as fail if citations are detached from claims, links are generic/broken, source roles are unclear, or the guide overstates evidence. |

## Result reporting template

For a real run, record:

```text
Scenario:
Host and date:
Mode selected:
Tools available:
Observed behavior:
Sources actually inspected:
Pass / partial / fail by criterion:
Integrity issues:
Unresolved limitations:
```

Do not compare performance with a built-in Deep Research system unless both workflows were actually run on equivalent prompts with documented conditions and independent scoring.
